## 01 — Software Engineering Fundamentals
 
Software Engineering is the disciplined, systematic application of engineering principles to the specification, design, development, testing, and maintenance of software, aimed at delivering reliable, efficient, and maintainable systems within cost and schedule constraints.
 
### Core Concepts
- **Software Crisis**: term (1960s–70s) for the set of problems large software projects faced — cost/schedule overruns, poor quality, unmaintainable code — as software size/complexity outgrew ad-hoc programming practices. It motivated formal SE as a discipline.
- **Software Process**: an organized set of activities, methods, and practices used to develop and evolve software.
- **Software Product**: the deliverable output of the process — either *generic* (sold on open market) or *custom* (built for a specific client).
- **Software Life Cycle**: all phases a software system passes through, from conception to retirement.
### Key Points
- Causes of software crisis: rapidly increasing size/complexity, absence of formal methodologies, poor project management, no standard quality measures, hardware costs falling while software costs rose.
- **Characteristics of good software**: Correctness, Reliability, Efficiency, Usability, Maintainability, Reusability, Portability, Testability, Interoperability.
- **SE Principles**: Rigor & formality, Separation of concerns, Modularity, Abstraction, Anticipation of change, Generality, Incrementality.
- **Software Development Activities** (broad categories): Specification → Design & Implementation → Validation → Evolution.
- **Software Metrics**: quantitative measures of a software product or process attribute, used for estimation, tracking, and quality control.
### Types / Classification
| Metric Category | Examples |
|---|---|
| Product metrics | LOC, cyclomatic complexity, function points |
| Process metrics | Defect density, productivity, review effectiveness |
| Project metrics | Cost, effort, schedule, staffing profile |
 
### Practical Takeaway
- The software crisis explains *why* process discipline (SDLC, reviews, metrics) exists — not bureaucracy for its own sake.
- SE principles (modularity, abstraction, separation of concerns) map directly to daily engineering practice (clean architecture, SOLID, etc.).
- Metrics convert vague quality/progress claims into measurable, trackable data.
### Quick Reference
| Term | Meaning |
